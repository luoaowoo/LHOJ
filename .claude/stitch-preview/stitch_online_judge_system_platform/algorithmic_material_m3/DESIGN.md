## Brand & Style

This design system translates the expressive, analytical, and fluid visual language of Google Material Design 3 (Material You) into the specialized, high-density realm of algorithmic problem-solving and competitive development. It bridges raw engineering rigor with modern human-centric design, providing maximum readability during high-stakes programming sessions.

The design philosophy unites:
- **Dynamic Surface Architecture:** Surfaces systematically stepped by luminance and tonal hue shifting, abandoning sterile pure blacks and stark monochromes in favor of nuanced container layers.
- **State-Driven Interaction:** Spatial depth conveyed through systematic state layers (hover 8%, focus 10%, press 12%) and surface-tint shifts rather than aggressive, high-contrast drop shadows.
- **Analytical Precision:** Seamless coexistence of expansive consumer-grade curved containers and dense, monospaced tabular data structures, mathematical notation, and terminal output.
- **Immediate Semantic Legibility:** Verdict-driven color accents engineered to signal execution states instantly under rapid visual scanning.

## Colors

The color palette is rooted in Material Design 3 tonal architecture. Derived from a deep technical cobalt base, it provides comfortable luminance for extended sessions in default dark mode, with dynamic primary, secondary, and tertiary groupings.

### Semantic Status & Execution Tokens
To guarantee unambiguous communication under cognitive load, execution verdicts use dedicated container and on-container pairings:
- **Accepted (AC):** `verdict-ac` (`#4ADE80`) over `verdict-ac-container` (`#052E16`).
- **Wrong Answer (WA):** `verdict-wa` (`#F87171`) over `verdict-wa-container` (`#450A0A`).
- **Time Limit Exceeded (TLE):** `verdict-tle` (`#FB923C`) over `verdict-tle-container` (`#431407`).
- **Memory Limit Exceeded (MLE):** `verdict-mle` (`#C084FC`) over `verdict-mle-container` (`#3B0764`).
- **Compilation Error (CE):** `verdict-ce` (`#FBBF24`) over `verdict-ce-container` (`#451A03`).
- **Runtime Error (RE):** `verdict-re` (`#FB7185`) over `verdict-re-container` (`#4C0519`).
- **Pending / Queue:** `verdict-pend` (`#94A3B8`) over `verdict-pend-container` (`#1E293B`).

### Surface Architecture
Hierarchy is formed by container lightness variations rather than border contrast:
- Base application surface sits at `surface` (`#111417`).
- Recessed environments, code editors, and terminals rest at `surface-container-lowest` (`#0B0E12`).
- Navigation drawers, structural rails, and inactive background segments map to `surface-container-low` (`#191C20`).
- Interactive default cards and work surfaces use `surface-container` (`#1D2024`).
- Floating toolbars, dialogs, and popovers ascend through `surface-container-high` (`#272A2E`) and `surface-container-highest` (`#323539`).

## Typography

The type system pairs the adaptable mechanics of `Roboto Flex` with the tabular structure of `JetBrains Mono`.

- **Prose & Layout:** `Roboto Flex` handles UI copy, headers, and statement text, balancing optical size parameters to retain legibility across variable viewport widths.
- **Code & Telemetry:** `JetBrains Mono` governs execution logs, telemetry readouts, status pills, runtime metrics, memory counters, and monospaced code blocks. It enforces tabular numbers (`font-variant-numeric: tabular-nums`) across all analytical tables.
- **Mathematical Formulations:** Inlined mathematical notations within problem statements align with the vertical baseline of `body-lg` (16px) or `body-md` (14px).

## Layout & Spacing

Layouts follow Material Design 3 responsive window size breakpoints, built around an 8dp structural grid and a 4dp micro-spacing unit for dense data presentations.

### Window Size Classes
- **Compact (< 600px):** 4 columns. Screen margins: 16px (`gutter-compact`). Navigation is pinned via an 80px fixed bottom navigation bar (`nav-bar-height`). Main workflows transition to stacked tabs (e.g., Problem Statement, Scratchpad, Submission Log).
- **Medium (600px – 839px):** 8 columns. Margins: 24px (`gutter-medium`). Navigation collapses to an 80px fixed left navigation rail (`rail-width`). 
- **Expanded (≥ 840px):** 12 columns. Responsive split-pane layout: problem statement column spans 55% width, while editor, I/O terminals, and execution controls occupy the remaining 45%, separated by an interactive vertical drag boundary.

## Elevation & Depth

Spatial layering adheres strictly to Material Design 3 tonal elevation tiers. Surfaces rise through calibrated dynamic surface-tint layers mixed with soft, low-contrast ambient occlusion rather than harsh drop shadows.

- **Level 0 (Flat):** Base canvas `surface` (`#111417`). 0px shadow. Used for canvas backdrops and background layout frames.
- **Level 1 (Default Containers):** `surface-container-low` (`#191C20`) with 5% surface-tint. Soft ambient shadow: `0px 1px 3px 1px rgba(0, 0, 0, 0.15), 0px 1px 2px 0px rgba(0, 0, 0, 0.30)`. Used for resting cards, input modules, and sidebar segments.
- **Level 2 (Active/Hovered Containers):** `surface-container` (`#1D2024`) with 8% surface-tint. Ambient shadow: `0px 2px 6px 2px rgba(0, 0, 0, 0.15), 0px 1px 2px 0px rgba(0, 0, 0, 0.30)`. Used for hovered cards and active split containers.
- **Level 3 (Floating Controls):** `surface-container-high` (`#272A2E`) with 11% surface-tint. Ambient shadow: `0px 4px 8px 3px rgba(0, 0, 0, 0.15), 0px 1px 3px 0px rgba(0, 0, 0, 0.30)`. Applied to Extended FABs, floating filter bars, and quick-action toolbars.
- **Level 4 (Dialogs & Drawers):** `surface-container-highest` (`#323539`) with 12% surface-tint. Ambient shadow: `0px 6px 10px 4px rgba(0, 0, 0, 0.15), 0px 2px 3px 0px rgba(0, 0, 0, 0.30)`. Applied to submission confirmation dialogs and sliding test-suite drawers.
- **Level 5 (Overlays & Menus):** `surface-container-highest` with 14% surface-tint. Ambient shadow: `0px 8px 12px 6px rgba(0, 0, 0, 0.15), 0px 4px 4px 0px rgba(0, 0, 0, 0.30)`. Applied to contextual drop-down menus, autocompletion popovers, and tooltips.

### State Layers
Interactive feedback uses uniform semi-transparent overlays on top of the component tokens:
- **Hover:** Component foreground color at 8% opacity.
- **Focus:** Component foreground color at 10% opacity.
- **Press:** Component foreground color at 12% opacity with centered radial ripple propagation.

## Shapes

The design system incorporates the expressive corner scales characteristic of Material Design 3, moving deliberately between fully rounded interactive tokens and structured container frames.

- **Full Pill (9999px):** All interactive action triggers (buttons, floating action buttons, segmented controls), status chips, verdict badges, and categorical search pills.
- **Extra Large (28px / `rounded-3xl`):** Primary modal sheets, contest summary banners, and standalone overview cards.
- **Large (16px / `rounded-2xl`):** Default card components, problem containers, and testbench runners.
- **Medium (12px / `rounded-xl`):** Input containers, text areas, and contextual filter popovers.
- **Small (8px / `rounded-lg`):** Code block containers, interactive table cell selection overlays, and sample I/O boxes.
- **Sharp (0px):** Structural split-pane dividing rails, full-bleed code editor frames, and console outputs.

## Components

### Buttons
- **Filled Button:** 40px height, full pill shape (`rounded-full`), padded 24px horizontally. Background `primary`, text `on-primary`. Used for primary workflow actions ("Submit Solution", "Register for Contest").
- **Tonal Button:** 40px height, full pill shape, background `secondary-container`, text `on-secondary-container`. Used for secondary actions ("Run Example Tests", "Generate Debug Input").
- **Outlined Button:** 40px height, full pill shape, 1px border in `outline`, transparent fill. Overlays an 8% `primary` state layer on hover.
- **Extended FAB:** 56px height, `rounded-2xl` (16px) or full pill shape, background `primary-container`, foreground `on-primary-container`. Houses primary workspace actions such as "Execute Scratchpad".

### Chips & Verdict Badges
- **Algorithm & Filter Chips:** 32px height, 8px rounded corners or full pill, 1px border in `outline-variant`. Typography is `label-md`.
- **Verdict Chips:** Full pill shape, 24px height, 10px horizontal padding, featuring monospaced `label-sm` labels. Uses matching verdict container background tokens with verdict text colors (e.g., `verdict-ac-container` with `verdict-ac`).

### Input Fields & Editor Blocks
- **Filled Text Field:** 56px height, rounded top (4px), bottom 2px active indicator in `primary`. Surface fill: `surface-container-highest`.
- **Outlined Text Field:** 56px height, `rounded-xl` (12px), 1px border `outline`, transitioning to a 2px `primary` border on focus.
- **Code Workspace:** Deep flat surface container (`surface-container-lowest`), zero corner radius inside split-views. Line numbers in `outline` tone. Active execution line styled with a 4% `primary` background tint.

### Cards & Container Panels
- **Problem & Contest Cards:** `rounded-2xl` (16px) or `rounded-3xl` (28px), 20px interior padding. Built on `surface-container` with Level 1 elevation, shifting to Level 2 on hover. Features problem title (`title-md`), difficulty rating pill, and acceptance metrics.

### Segmented Buttons
- Multi-option selectors (e.g., programming language switchers: "C++20", "Rust", "Python 3") rendered as connected pill-shaped clusters with 40px height. Active segments receive `secondary-container` fills with `on-secondary-container` text, bordered by 1px `outline-variant`.

### Navigation Rail & App Bar
- **Navigation Rail:** 80px fixed width, background `surface`. Destination icons center within 32px height by 56px width pill indicators (`secondary-container`) when active.
- **Top App Bar:** 64px height, background `surface`, elevating to `surface-container` on content scroll. Houses breadcrumbs, contest countdown timers, and system profile controls.
